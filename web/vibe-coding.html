Vibe Coding(氛围编程)到底是什么

Vibe Coding 的核心是意图优先:开发者关注"要什么",而不是逐行"怎么写"。它通常包含三层:

  • 自然语言输入:用中文或英文描述功能、修复或整块任务。
  • AI 生成与迭代:模型写代码、跑测试、按结果自我修正。
  • 人做验收:你审查最终结果,而不是每一步的中间产物。

它的价值在于降低"从想法到可运行"的摩擦;它的风险在于缺少审查与验证。选择工具时,差别往往在自主程度和验证闭环,而不只是补全速度。

Vibe Coding 适合、不适合什么

适合

  • 需求相对清晰、可以被描述成任务的功能开发与重构。
  • 有测试或可验证输出的场景——AI 能自己判断"做没做对"。
  • 需要跨多个会话推进的中长期项目。

要谨慎

  • 安全、资金、合规等高风险逻辑——必须人工复核。
  • 需求本身模糊、反复摇摆——先想清楚再交给 AI。
  • 没有验证手段的改动——AI 会"看起来完成",但没人能证明。
