## 1. M1 — 旗舰架构线（deck 的主体）

### 已完成并有多种子实证（✅ = deck 可引用）

| 项 | 结果 | 状态 |
|---|---|---|
| 20K 收敛三方对比（3 seeds, fp32, WikiText-103）| modern Transformer **78.86±0.25** < MT-LNN **88.93±0.33** < simple Transformer **94.14±0.78** val PPL | ✅ 诚实记录：**落后现代基线 11.3%** |
| O(1) 推理内存证据扩展到 1M tokens | 携带状态恒定 **0.381 MB**（512→1,048,576，2048× 上下文增长），KV 对照线性涨到 3,072 MB → **8,063×** | ✅ 最强主张，deck 主打 |
| 跨窗口/跨会话联想召回 | **0.56 vs 0.000**（注意力/LoRA 结构性为零）；消融快权重塌到 0.008；快照恢复逐位无损 | ✅ 第二主张 |
| NASA 电池 SoH 端侧 pilot（2026-07-24）| 规则采样下四架构精度统计打平（MT-LNN 参数少 2.6×）；**不规则采样是唯一真差异化**：80% 丢弃仅退化 **+7.7%** vs LSTM **+31.1%** / GRU **+32.8%**（t=+2.40/+2.63 显著）；流式状态恒定 2.6 KB | ✅ deck 场景页数据来源 |
| fp16 发散根因修复 | `global_coherence` 的 `(Q@K)/scale` 缩放顺序导致中间乘积溢出 fp16 → 修复后 fp16 (257.91) = fp32 (257.48) 质量 | ✅ |
| ONNX 导出打通 | 数值误差 3.58e-07，48M → ~66MB int8，浏览器可下发（须 `dynamo=False`） | ✅ 浏览器 demo 的前提 |
| M2 适配器（v2s 双语 SFT）上生产 | 8.4M 适配器参数（v1 是 62.8M），24MB vs 129MB；awareliquid.ai adapter 服务在跑；金融文档 91.7%（44/48） | ✅ |
| 测试体系 | **1232 项测试全绿**（2026-07-31 实测），契约固定 | ✅ |

### 明确的架构问题（M1）

1. **PPL 质量差距是第一硬伤**：对现代 Transformer（RoPE+RMSNorm+SwiGLU）落后 11.3%。论文与产品叙事都已改为"效率与记忆形态优势"，但缩小差距正是 M2 的存在理由。
2. **生物默认值会静默阉割能力（P0 最大教训）**：GTP-cap 距离衰减 init（4 头 γ = [0.8, 0.2, 0.05, 0.0125]）把 3 个头的远视力干掉，直接阻断归纳头形成 → 关系推理钉死 0.25；修复（γ 全局化 + full MHA）后 **1.0000 满分**，反超 transformer 对照 0.9932。`n_global_heads` 已进 config，但**默认仍为 0、sweep 未做**——修复还没变成默认行为。
3. **Hebbian 模块实测惰性**（PPL 贡献 < seed 噪声），按 ROADMAP 纪律应改造成 fast-weights / test-time learning 或直接删除，尚未执行。
4. **强基线未补齐**：Mamba-2 / GLA / DeltaNet / RWKV-7 对照全部缺席（需 A100）。当前"vs Mamba −37.8%"是 2K 步旧口径 + 宽度不匹配基线，不能进论文主表。效率对比另有红线：不能用 Windows 上纯 PyTorch 的 `mamba.py` 慢实现代表 Mamba 速度（一测就被拆穿）。
5. **⚠️ 内部文档泄漏在公开仓库**：`PUBLICATION_READINESS.md` 文件头写着"内部文档，勿推公开仓库——公开等于向审稿人/竞品自曝短板，默认已排除出 git"，**但它实际一直被 git 跟踪且公开可见**（现位于 `docs/reviews/`）。需要决策处置。
6. **工程侧**（2026-07-31 已部分处理）：根目录已整理、非模型资产已迁出到本仓库；仍遗留 60+ 模块平铺的 `mt_lnn/` 命名空间、生产 checkpoint 提交在 git 里、研究仓 main 直接驱动生产部署（服务器 `git pull` M1）。
7. **命名冲突**：仓库 O1（前身原型）≠ 产品线 O 系列 O1（M1 内的 ARR 无注意力线）。对外沟通持续踩混淆。

## 2. M2 — 2B 推理引擎工作流（M1 内，deck 路线图的支撑）

**命题**：知识外置 RAG，2B 本体 = 纯推理引擎 + 记忆控制器；只在四轴（数学/代码推理、长流式记忆、持续学习、端侧延迟内存）对标 70B **base**，**不承诺全面对标**（知识容量随参数缩放是物理规律）。

**现状诚实评估**（ROADMAP 原文）：*"M1 现在赢在效率与记忆形态，不赢在思考能力。M2 的全部工作就是补思考能力。"*

### P0 进展（2026-07-28/29，五轮实验，负结果全记录）

- ❌ **"只循环液体核心 = 思考"被证伪**：fixed-depth sweep 下深度 1/2/4/8 结果全平（0.289/0.297/0.293/0.293，差异在噪声内）；组合查找的计算发生在注意力里
- ❌ 朴素随机深度训练**教会模型"无视迭代"**——深度不变解是最容易的优化路径
- ✅ **正面产出 = 架构原则 #1（全局头配额）**：排除法（关液体递归 +0.04、注意力层翻倍 0 帮助）锁定 MicrotubuleAttention 的 GTP 衰减为阻断器，GQA 为协同因素；修复后满分。**并证明液体子层本身无罪**
- ✅ 代码全部落地且零回归：`core_iterations`（N=1 位等价）/ `stack_iterations` / `n_global_heads`（默认 0 位等价）/ 深度敏感基准 / 深度实验框架

### 下一步（按 ROADMAP 的止损纪律）

- **P0-C′**：在"注意力已修复"的模型上重验思考深度命题（更多跳数/更大图）——**这是 M2 全部命题的 go/no-go**
- **P0-D**：生物模块清理（Hebbian → fast-weights 或删；GWT/PC 补 ablation）
- **P1**（数百美元云预算）：蒸馏优先（Qwen3 教师推理轨迹 → 350M–1B 学生，反向 KL + μP 缩放验证），**不做从零预训练**；评测切换 GSM8K / MATH-500 / ARC / RULER
- **P2**（融资后）：2B 混合架构（液态为主 + 少量滑窗注意力，Jamba/Zamba/Samba 证据）、GRPO 后训练、surprise 门控记忆控制器、睡眠期蒸馏固化

## 4. O1-Anti — 反 Transformer 研究线（🟡 有一个干净的正结果）

**三支柱**：NLA（神经液态邻接，替代注意力的序列混合器）· 上下文路由稀疏计算（Neural Module Graph）· 非自回归生成。2026-05-08 从 MT-LNN 代码库分叉，2026-07-09 转向 Anti-Transformer 定位，2026-07-16 最后一笔提交正是"RETRACT E10"——自己撤回自己的正结果。

### 验证记分卡（诚实版）

| 声明 | 判定 |
|---|---|
| NLA 是内存高效混合器（cache 小 6–8×） | ✅ 成立（解析 + P1） |
| NLA **召回质量持平注意力**（MQAR，wd=0.1，多种子，pairs 8/16） | ✅ 成立 —— **唯一干净的正结果** |
| 三支柱可组合成端到端模型（P4：74% 激活、7 pass vs 48） | ✅ 玩具规模成立 |
| 非自回归生成 3.4× 更少 pass（P3） | ✅ 玩具规模成立 |
| 路由稀疏计算 27% 激活达 100% 准确（P2） | ✅ 玩具规模成立 |
| NLA 真实文本检索胜 dense（E10） | ❌ **已撤回**（weight-decay 伪影；两边都正则化后打平） |
| NLA 通用语言建模持平 dense（E8） | ❌ 失败（−22% BPB，5 组消融不救，含 multi-head NLA 假说被证伪） |
| "NLA Router"专家拓扑路由是差异化 | ❌ 消融无收益（3.366 vs 3.371，< 种子噪声，且多 2.6% 参数） |
| 权重 VQ 压缩 30–50% | ❓ 从未测过（E9 验证的是潜变量编解码，不是权重） |
| 160B / <100万 RMB / MMLU>65% 计划 | ❌ 无任何缩放证据，已在 POSITIONING 中正式废弃 |

**诚实定位**（`O1ANTI_POSITIONING.md`）：不是 DeepSeek 竞争者，甚至还不是已验证的检索专家；是"**召回质量持平注意力、cache 便宜 6–8 倍的混合器**"这个假说 + 一个合成任务数据点。证据门控路线图：**Stage 0**（补干净 Mamba@wd=0.1 对照 + pairs=32，几个 GPU 时）→ **Stage 1**（100–300M NLA+注意力混合模型跑检索基准套件）→ **Stage 2**（三规模缩放曲线）→ **Stage 3**（曲线说了算，不预设 160B）。

**与 M1 的关系（重要）**：O1-Anti 的 hybrid trunk（NLA + 间隔全注意力，Jamba/Zamba 模式，代码已实现）与 M2 P2 的"液态为主 + 少量滑窗注意力"是**同一个设计问题的两个实验场**。Stage 1 结果应直接喂给 M2 的混合层配比决策（M1 外部评审已把 hybrid ratio 列为待决事项）。两条线合流可以省掉一半算力。另有副产物 `AwareLiquid-Physic`（哈密顿物理头 + 辛积分）已并入 M1 的 physics-informed-head 分支。
