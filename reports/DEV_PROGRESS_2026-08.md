### 明确的架构问题（M1）

1. **PPL 质量差距是第一硬伤**：对现代 Transformer（RoPE+RMSNorm+SwiGLU）落后 11.3%。论文与产品叙事都已改为"效率与记忆形态优势"，但缩小差距正是 2B 路线的存在理由。
2. **生物默认值会静默阉割能力（P0 最大教训）**：GTP-cap 距离衰减 init（4 头 γ = [0.8, 0.2, 0.05, 0.0125]）把 3 个头的远视力干掉，直接阻断归纳头形成 → 关系推理钉死 0.25；修复（γ 全局化 + full MHA）后 **1.0000 满分**，反超 transformer 对照 0.9932。`n_global_heads` 已进 config，但**默认仍为 0、sweep 未做**——修复还没变成默认行为。
3. **Hebbian 模块实测惰性**（PPL 贡献 < seed 噪声），按 ROADMAP 纪律应改造成 fast-weights / test-time learning 或直接删除，尚未执行。
4. **强基线未补齐**：Mamba-2 / GLA / DeltaNet / RWKV-7 对照全部缺席（需 A100）。当前"vs Mamba −37.8%"是 2K 步旧口径 + 宽度不匹配基线，不能进论文主表。效率对比另有红线：不能用 Windows 上纯 PyTorch 的 `mamba.py` 慢实现代表 Mamba 速度（一测就被拆穿）。
5. **⚠️ 内部文档泄漏在公开仓库**：`PUBLICATION_READINESS.md` 文件头写着"内部文档，勿推公开仓库——公开等于向审稿人/竞品自曝短板，默认已排除出 git"，**但它实际一直被 git 跟踪且公开可见**（现位于 `docs/reviews/`）。需要决策处置。
6. **工程侧**（2026-07-31 已部分处理）：根目录已整理、非模型资产已迁出到本仓库；仍遗留 60+ 模块平铺的 `mt_lnn/` 命名空间、生产 checkpoint 提交在 git 里、研究仓 main 直接驱动生产部署（服务器 `git pull` M1）。
7. **命名冲突**：仓库 O1（前身原型）≠ 产品线 O 系列 O1（M1 内的 ARR 无注意力线）。对外沟通持续踩混淆。

## 2. M1 的 2B 推理引擎路线（`docs/ROADMAP_M2.md`，架构工作流）

> 这是 M1 仓库内的架构路线图，**与 `AwareLiquid-M2` 仓库无关**（见开头的命名冲突说明）。

**命题**：知识外置 RAG，2B 本体 = 纯推理引擎 + 记忆控制器；只在四轴（数学/代码推理、长流式记忆、持续学习、端侧延迟内存）对标 70B **base**，**不承诺全面对标**（知识容量随参数缩放是物理规律）。

**现状诚实评估**（ROADMAP 原文）：*"M1 现在赢在效率与记忆形态，不赢在思考能力。M2 的全部工作就是补思考能力。"*

### P0 进展（2026-07-28/29，五轮实验，负结果全记录）

- ❌ **"只循环液体核心 = 思考"被证伪**：fixed-depth sweep 下深度 1/2/4/8 结果全平（0.289/0.297/0.293/0.293，差异在噪声内）；组合查找的计算发生在注意力里
- ❌ 朴素随机深度训练**教会模型"无视迭代"**——深度不变解是最容易的优化路径
- ✅ **正面产出 = 架构原则 #1（全局头配额）**：排除法（关液体递归 +0.04、注意力层翻倍 0 帮助）锁定 MicrotubuleAttention 的 GTP 衰减为阻断器，GQA 为协同因素；修复后满分。**并证明液体子层本身无罪**
- ✅ 代码全部落地且零回归：`core_iterations`（N=1 位等价）/ `stack_iterations` / `n_global_heads`（默认 0 位等价）/ 深度敏感基准 / 深度实验框架

### 下一步（按 ROADMAP 的止损纪律）

- **P0-C′**：在"注意力已修复"的模型上重验思考深度命题（更多跳数/更大图）——**这是 2B 路线全部命题的 go/no-go**
- **P0-D**：生物模块清理（Hebbian → fast-weights 或删；GWT/PC 补 ablation）
- **P1**（数百美元云预算）：蒸馏优先（Qwen3 教师推理轨迹 → 350M–1B 学生，反向 KL + μP 缩放验证），**不做从零预训练**；评测切换 GSM8K / MATH-500 / ARC / RULER
- **P2**（融资后）：2B 混合架构（液态为主 + 少量滑窗注意力，Jamba/Zamba/Samba 证据）、GRPO 后训练、surprise 门控记忆控制器、睡眠期蒸馏固化

## 3. M2 — 长文档 QA 的外部记忆压缩适配器（🟢 最接近可交付）

**仓库**：`AwareLiquid/AwareLiquid-M2`（公开）· 30 次提交，2026-07-18 → 07-26 · **一周内从零做到 91.7%**

### 它是什么

一个**不碰模型权重**的适配器：基座 LLM 冻结、只通过 HTTP API 调用，索引 / 检索 / 覆盖 / 压缩全部在本地跑，只有压缩后的提示词和简短答案计费。三条硬约束定义了全部设计：

1. 基座冻结——仓库里没有任何训练/微调代码
2. **答案路径上不许有 embedding / rerank 模型**——检索纯词法（SQLite FTS5 上的 BM25 + 文档结构）
3. 硬性 token 总预算——由崩溃安全、跨进程加锁的账本计量，超预算即失败关闭

| 阶段 | 模块 | 做什么 |
|---|---|---|
| 索引 | `adapter/evidence_index.py` | 切成带页码/章节/条款号/表格行列和数值锚点（年份、金额、%、评级）的证据节点 |
| 存储 | `memory/lexical_store.py` | FTS5 上 11 列**字段加权** BM25（条款号与锚点权重 6×）、显式中文 n-gram 扩展、结构化重排、邻域扩展 |
| 检索 | `adapter/qa_agent.py` | 多查询：原问题 + 每个时间操作数一个锚点增强子查询 + 每个选项一个，按最佳排名取并集；文档过滤在扫描内部完成 |
| 压缩 | `adapter/compressor.py` | 抽取式、**零 LLM 调用**的句子选择，为每个段落和每个选项预留覆盖额度，防止某个选项被饿死 |
| 作答 | `adapter/qa_agent.py` | 逐选项 SUPPORTED/REFUTED/INSUFFICIENT 结构化判断 + 可选的本地 `Decimal` 算术复核 |
| 计费 | `adapter/qwen_client.py` | OpenAI 兼容客户端，精确到每次调用的 token 记账 + 持久化预算账本 |

### 实测状态

| 项 | 结果 |
|---|---|
| 测试 | **179 项通过**（Windows + POSIX：契约、检索、压缩、答案解析、账本并发、断点续跑） |
| Token 成本 | **每题约 1.3 次模型调用、约 2.8k tokens**（`benchmarks/bench_token_cost.py` 端到端实测） |
| 48 题评测集（全 5 个金融文档域） | **44/48 = 91.7%**，约 377k tokens（self-consistency 3） |
| 22 题评测集（3 域） | 20/22 = 90.9%，约 207k tokens |
| 分类型 | 事实查找 18/19 · 条款定位 6/6 · 时限 2/2 · 范围 3/3 · 观点vs事实 2/2 · 跨文档比较 4/4 · 计算 6/7 · **多文档推理 3/5** |
| 分格式 | mcq 26/28 · tf 10/10 · **多选 8/10** |

**这就是 deck 里"金融文档 91.7%（44/48）"的出处**——我此前误记为 M1 的适配器结果，实为本仓库。

### 已知问题（仓库自己诚实列出，值得原样保留）

1. **多选是明确弱点**，且投票救不回来：探查一次失败的逐样本投票，正确选项得 **0/3** 票、错误选项 **3/3**——这是跨文档否定（"X 被排除" vs "X *不*被排除"）上的**稳定推理错误**，不是噪声。没有任何投票阈值能救一个从来不得票的选项。
2. **服务商在 `temperature=0` 下仍非确定性**（MoE 路由 / 服务端 batching），同一题重跑会翻转。所以准确率是分布不是点值，n=22 的单次 A/B 分辨不出小改动。
3. **评测集是随系统一起写的**——它衡量的是流水线（检索找没找到、压缩留没留住答案句、解析对不对），**不是真实世界难度**。是回归基线，不是排行榜。
4. **检索 vs 直接截断的权衡完全未测**——已发表的同类结果里有朴素截断**打赢**分块检索的，这个适配器赌了另一边，而这个赌注在此处没被验证过。
5. 算术问题没有代码执行路径，本地只复核模型给出的计算账本。

### 判断

**这是四条线里唯一现在就能拿去谈客户的东西**：不依赖算力、不依赖融资、有真实评测数字、有容器化的批处理入口（`submit.py`，断点续跑 + 契约校验的 CSV 输出）。同时它的诚实度是标杆——"评测集是自己写的，所以是回归基线不是排行榜"这句话，很多公司不会写。

**风险**：它跟 AwareLiquid 的架构故事（液态神经网络、O(1) 记忆）**技术上毫无关系**。对外要想清楚它是"同一个愿景的产品化第一步"还是"另一条业务线"——现在 deck 里把它的数字和架构成果混在一起讲，逻辑上是断的。

## 4. O1-Anti — 反 Transformer 研究线（🟡 有一个干净的正结果）

**三支柱**：NLA（神经液态邻接，替代注意力的序列混合器）· 上下文路由稀疏计算（Neural Module Graph）· 非自回归生成。2026-05-08 从 MT-LNN 代码库分叉，2026-07-09 转向 Anti-Transformer 定位，2026-07-16 最后一笔提交正是"RETRACT E10"——自己撤回自己的正结果。

### 验证记分卡（诚实版）

| 声明 | 判定 |
|---|---|
| NLA 是内存高效混合器（cache 小 6–8×） | ✅ 成立（解析 + P1） |
| NLA **召回质量持平注意力**（MQAR，wd=0.1，多种子，pairs 8/16） | ✅ 成立 —— **唯一干净的正结果** |
| 三支柱可组合成端到端模型（P4：74% 激活、7 pass vs 48） | ✅ 玩具规模成立 |
| 非自回归生成 3.4× 更少 pass（P3） | ✅ 玩具规模成立 |
| 路由稀疏计算 27% 激活达 100% 准确（P2） | ✅ 玩具规模成立 |
| NLA 真实文本检索胜 dense（E10） | ❌ **已撤回**（weight-decay 伪影；两边都正则化后打平） |
| NLA 通用语言建模持平 dense（E8） | ❌ 失败（−22% BPB，5 组消融不救，含 multi-head NLA 假说被证伪） |
| "NLA Router"专家拓扑路由是差异化 | ❌ 消融无收益（3.366 vs 3.371，< 种子噪声，且多 2.6% 参数） |
| 权重 VQ 压缩 30–50% | ❓ 从未测过（E9 验证的是潜变量编解码，不是权重） |
| 160B / <100万 RMB / MMLU>65% 计划 | ❌ 无任何缩放证据，已在 POSITIONING 中正式废弃 |

**诚实定位**（`O1ANTI_POSITIONING.md`）：不是 DeepSeek 竞争者，甚至还不是已验证的检索专家；是"**召回质量持平注意力、cache 便宜 6–8 倍的混合器**"这个假说 + 一个合成任务数据点。证据门控路线图：**Stage 0**（补干净 Mamba@wd=0.1 对照 + pairs=32，几个 GPU 时）→ **Stage 1**（100–300M NLA+注意力混合模型跑检索基准套件）→ **Stage 2**（三规模缩放曲线）→ **Stage 3**（曲线说了算，不预设 160B）。

**与 M1 的关系（重要）**：O1-Anti 的 hybrid trunk（NLA + 间隔全注意力，Jamba/Zamba 模式，代码已实现）与 2B 路线 P2 的"液态为主 + 少量滑窗注意力"是**同一个设计问题的两个实验场**。Stage 1 结果应直接喂给 2B 路线的混合层配比决策（M1 外部评审已把 hybrid ratio 列为待决事项）。两条线合流可以省掉一半算力。另有副产物 `AwareLiquid-Physic`（哈密顿物理头 + 辛积分）已并入 M1 的 physics-informed-head 分支。

## 5. 行动清单

### 🔥 短期（0–4 周，多数不需要新预算）

1. **给 M2 改名，消除命名冲突**——`AwareLiquid-M2` 和 `M1/ROADMAP_M2.md` 是两个完全不同的东西，现在共用一个代号。半小时的事，但拖着会持续制造误解（本报告上一版就搞混了）。建议适配器改叫 `AwareLiquid-DocQA` 或 `AwareLiquid-Adapter`
2. **M2 多选弱点定点攻关**——4 个失败里 3 个是多选，且已定位到根因（跨文档否定的稳定推理错误，不是噪声）。这是提升评测分最直接的一刀，且不需要算力
3. **补测 M2 的"检索 vs 截断"对照**——仓库自己列为未测，而已发表结果里有截断打赢检索的。这是整个适配器的**核心假设**，没验证等于赌
4. **2B 路线 P0-C′ 思考深度重验**（本地 8GB 可做）——该路线全部命题的 go/no-go
5. **`n_global_heads` sweep 并改默认值**——架构原则 #1 只有变成默认配置才算真正落地；同时写进论文叙事（值得作为论文的一个 finding）
6. **P0-D 生物模块清理**——Hebbian 改 fast-weights 或删；GWT/PC 补 5-seed ablation
7. **O1-Anti Stage 0**（几个 GPU 时）——干净 Mamba@wd=0.1 对照 + pairs=32，把唯一的正结果做严实
8. **PUBLICATION_READINESS 移出公开仓库**（O1 的文档清理已于 2026-08-01 完成）
9. **租 A100（AutoDL 已有环境）**：补 P0-3 剩余强基线（Mamba-2 / GLA / DeltaNet / RWKV-7，须用 CUDA kernel 版）+ 真实长上下文（RULER）——论文投稿的硬门槛

### 🚧 中期（1–3 个月）

1. **M2 找 2–3 个真实客户验证**——这是唯一不等算力、不等融资就能产生商业信号的东西。金融/法律/合规文档 QA，按 token 计费的场景最匹配它的设计

4. **O1-Anti Stage 1 混合模型** → 结果并入 2B 路线的混合层配比决策，两条线合流，避免重复烧算力
5. **论文投稿**（ICLR / NeurIPS 主会，Track A 工程路线）：主张收敛到"质量-效率折中 + O(1) 长上下文"，意识 / Φ / 麻醉全部移出正文

## 7. 一句话结论

**技术资产是真的，证据纪律是稀缺优势，但四条线目前是"一个能卖的产品 + 三个被算力卡住的研究方向"，而不是一条主线。**

最紧要的四件事：
1. **认清 M2 是当下唯一能产生商业信号的东西**——不等算力、不等融资、有真实数字，应该配资源去找客户，而不是当成副产品
2. **给 M2 改名并厘清它与架构故事的关系**——技术上它跟液态神经网络无关，对外要么讲成"产品化第一步"（并说清路径），要么单独成线，不能混着讲
3. **用 P0-C′ 给 2B 路线一个明确的 go/no-go**，并把 O1-Anti 的 hybrid 实验并进同一个决策，两条线合流
4. **拿到 A100 预算补齐强基线**，让论文能投出去——这是架构线唯一的出口
